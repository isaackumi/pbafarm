# 15 — Technical Debt Register

Discovery stage: synthesis of docs 01–14 (MASTER-PROMPT PART 12, item 15). Branch `docs/discovery`, 2026-11-18. Docs only.

## Stage header

| Item | Value |
|---|---|
| Objective | One deduplicated register of every defect, risk and structural debt found in discovery docs 01–14, with evidence, category, severity, effort, blast radius and the roadmap item that retires it. |
| Inputs | Discovery docs 01–14. Every row cites the discovery finding it came from and the source `file:line` that finding cites. Source was spot-checked for the rows marked † (`convex/lib/authz.ts`, `convex/lib/tenancy.ts`, `convex/harvest.ts:107-187`, `convex/schema.ts` `cages`). |
| Method | Findings that appear in several docs (for example "deactivated users keep access" in 04, 06, 07 and 12) were merged into one row; the "Source findings" column lists all of them. Where docs disagree on severity, the higher severity is kept and the reason is given. |
| Completion status | Complete for what discovery found. Nothing here was verified against a running deployment; the confidence of each source finding carries over. |

### Column definitions

- **Category**: `security`, `integrity` (stock, counts, money or history can become wrong), `scale` (fails or degrades as data or tenants grow), `UX`, `code health`, `ops`.
- **Severity**: Critical (silent corruption, cross-tenant exposure or total outage reachable in normal use), High, Medium, Low.
- **Effort**: S (≤ 2 days, local change plus tests), M (≤ 2 weeks, several modules or a backfill), L (multi-week, new subsystem or migration).
- **Blast radius**: what is affected if the item fails or is changed.
- **Link**: roadmap phase / tracker ID per decision D-013. Fixed IDs: `SEC-001`, `SEC-002`, `PROD-000`, `OPS-001`, `PLAT-001`, `ORG-001`. Otherwise the phase prefix with `*`, meaning the number is assigned in `docs/project-management/MASTER-TRACKER.md`. "Phase 0" means the item is in the D-013 Stabilize list.
